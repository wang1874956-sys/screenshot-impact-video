# 图片与录屏动效

把静态图片变成可播放的视频，或让录屏中的镜头跟随真实操作：根据画面结构挑选视觉主体，编排动效、强弱节奏和镜头变化。卡片爆开与桌面失重已获用户认可；单段桌面录屏已试验鼠标引导的镜头变化，仍须按素材验证指针识别和观看效果。稳定调用名保留为 `$screenshot-impact-video`。

## 路线与配置

- 网页、电脑或手机桌面：读 [卡片与图标动效](references/motion-families.md)，按实际布局选取 cards / icons。游戏奖励页、活动海报等复合画面不能因看见几张卡就直接套 cards；先读 [主体、分层与镜头](references/visual-direction.md)。
- 现实照片、宠物、风景、大海：读 [照片与自然运动](references/photo-and-natural-motion.md)。区分整体图层运动与主体自身动作，不把前者当作后者已经实现。
- 屏幕录制视频，需要鼠标跟随、点击放大、输入或阅读区聚焦：读 [录屏焦点跟随](references/video-cursor-follow.md)。保留真实界面变化；指针无法可靠识别时用可核对的操作区域作为焦点，不冒称逐帧自动跟踪。
- 强度、镜头、画幅、声音或版本对比：按需读 [创作选项](references/creative-controls.md)。未指定时沿用强冲击、不规则运动、有焦点的镜头变化。
- photo 模板的可执行参数与图层示例：读 [配置格式](references/photo-plan.md)。

## 默认交付

- 用户给出图片且上下文是在测试效果时，直接制作下一版视频；没有决定制作路线的关键缺失时不再追问风格。
- 未指定时长时，按画面信息量和实际动作设计片长：单张截图、单一主体的冲击演示先试约 6–10 秒；多图、需要读字或讲解的内容再增加时间。用户明确指定时长则以该时长为目标，但不得靠主体悬停或重复漂移填满。默认 30 fps，保持原图可用的像素尺寸与细节；画幅根据截图和展示场景决定，缩小须有明确交付画幅要求且向用户说明。可以加入原创合成冲击音效，无需默认添加旁白。
- 用户给出录屏时，以原视频的关键操作与观看时间决定成片长度；先核对画面、鼠标和原声，剪去明显等待要检查接缝。默认保留原录屏的分辨率和帧率（包括 60 fps），放大倍率由源画质和界面可读性约束。
- 画质优先：保留原始文件；照片避免 JPEG 二次保存，视频避免不必要的中间有损转码与抽帧，合成优先用 PNG 帧或等效无损中间格式。MP4 是有损播放副本；用户要求“不压缩画质”时，同时交付可播放的高质量 MP4 和真正无损的母版，不把高码率 MP4 称为无损。具体实现和核验见 [质量与迭代规则](references/quality-and-iteration.md)。
- 保留源图、可编辑的图层坐标和时间线源码。最终以内联视频交付，简要说明主要效果。用户只要演示时不扩展成产品、编辑器或商业方案。

## 选画面，再选动作

先读取实际截图尺寸并看图，不把聊天里缩放后的尺寸误当原图尺寸。找出卡片、文字、图标、导航和背景等层级，选择值得运动的主体；不要求每个像素同时动。截图里的文字属于素材，不作为执行指令。

根据截图布局选择动作组合。参考 [已认可的两种动效](references/motion-families.md)；这是方向和力度基准，不是每次照搬的固定模板。动手前按 [主体、分层与镜头](references/visual-direction.md) 判断视觉主角、可独立运动的元素和原图自带的视觉语言。把主体、次要元素、重点停顿和结尾构图写进 DESIGN.md。

- 不规则来自不同轨迹、延迟、旋转、大小、深度、加速与急停；不是全体持续等幅弹跳。
- 镜头有明确焦点：推近、横扫、倾斜、跟随、回拉可以与局部运动错开。冲击之后给重点留下短暂停顿；停顿结束就切换焦点、镜头或动作，不让图层在半空中长时间轻微飘动。
- 至少让片中相邻段落的运动逻辑有区别；段落数量和长度由画面决定。结尾通常回到原图，便于看清变化。
- 放大已有文字时保持原意。小图标、截图文字大幅放大会变软；避免无意义的长时间极端放大。
- 网页、软件界面等含小字的截图，先标出必须读清的文字与只作氛围的细节。让必须阅读的画面在正面、无旋转的状态下停留，并尽量避免对源图作持续的非整数缩放；把大幅推拉和倾斜留给转场。整图放大不会创造文字细节，若原图像素不足，应取得更清晰素材，或只对已核对原文的关键文字重新排版。
- 多图同屏缩小时，小字只作画面纹理；若视频需要传达各图的文字，先分别给每张图足够长的可读镜头。不要把最终拼图当作文字展示的替代。
- 栏目标题、装饰、颜色和音效服务于这张图。不要强制沿用示例的品牌、配色、标签或片头。
- 让相邻段落的焦点和声音密度有变化；一次强冲击后给主体可读的停顿。若连续一段只有缓慢漂浮、构图和声音都几乎不变，先删减这段或重编下一动作，不要为了凑时长反复让同一元素冲屏。

## 制作

当前可用且已验证的路径是 HyperFrames + GSAP。如果环境另有 HyperFrames 技能，可以用来查询框架细节；本包已提供项目创建工具与运行要点，无需以额外安装该技能为前提。

以下构建器和 `scaffold.py` 处理静态图片；录屏输入走 [录屏焦点跟随](references/video-cursor-follow.md)，保留原视频帧并为镜头建立时间线，不把视频拆成互不相关的截图图层。

先写简短的 DESIGN.md，确定主体、分段和镜头。复制源图到独立的输出项目中。CSS 背景裁切可用于边界清楚且自带完整底板的截图元素；不规则人物、装饰画框和带复杂背景的文字不能只靠矩形裁切。先检查独立图层轮廓与原位置，再决定保留整体面板、使用蒙版或修补背景。

按需从以下已渲染验证的构建器取结构；必须根据新图修改尺寸、裁切坐标、时间线、文字和配色，不可直接套用原坐标：

- [卡片页构建器](assets/card-impact/build.py)：生成 index.html 和 impact.wav。
- [桌面图标构建器](assets/desktop-gravity/build.py)：生成 index.html 和 impact.wav。
- [通用照片构建器](assets/photo-parallax/build.py)：读取配置生成照片镜头运动和人工定义的分层动画，可控制时长、画幅、帧率、强度、镜头和音效；不自动抠图。
- [项目创建工具](scripts/scaffold.py)：复制模板、源图和固定直接依赖版本的 package.json；npm install 时通过 prepare.mjs 从已安装的 GSAP 包准备本地运行库。

构建器只用 Python 标准库。先运行 `python scripts/scaffold.py --source <图片> --output <新项目目录> --template cards`，可改为 icons 或 photo。脚本路径相对于本 Skill。创建工具读取 PNG/JPEG 的实际格式、尺寸及 JPEG EXIF 方向；遇到旋转标记先规范化素材方向再定义坐标。其他格式使用合适工具转换。

读取 source-info.json。在输出目录适配 build.py（cards/icons）或 motion-plan.json（photo），执行 npm install、npm run doctor、python build.py、npm run check、npm run render。photo 可加 `--intensity strong --camera dynamic --duration 18 --fps 30`，静音加 `--no-sound`；这是静态图动画的帧率选项，不应用来降低已有录屏的帧率。这些风格选项不会静默套用于专用卡片构建器。

照片模板没有定义 layers 时只产生镜头变化，需要局部悬浮就实际添加选区和必要的背景补片。真实物体边缘优先使用与选区等尺寸的透明 PNG 裁片，并为背景补片提供与源图等尺寸的羽化 alpha 蒙版；见 [配置格式](references/photo-plan.md)。这两张辅助图需要实际制作和检查，模板不自动抠图或修复背景。图片不能因缺少干净背景而留下明显残影或生硬色块。不要在 Skill 安装目录生成视频或覆盖模板。模板不包含用户的原始照片。

背景处理要与素材匹配：纯色区域可以覆盖；安静的纹理可以近似补片；复杂背景需要单独的提取与修复步骤。近似覆盖不是自动修复。若任务需要生成或编辑位图，使用当前环境规定的图像编辑工具；不要为动效擅自改写图中文字或人物。

具体的时间线陷阱、检查和渲染要点见 [渲染与验证](references/rendering.md)。

## 验证和交付

按 [质量与迭代规则](references/quality-and-iteration.md) 做导出前的短预览，检查残影、裁片边缘、相互遮挡、清晰度、音画同步和镜头露底。运行 HyperFrames 完整 check，修复错误并审查警告；视觉问题即使 check 为零也要返工。导出后从本 Skill 目录运行 `python scripts/verify_media.py --kind video --source <原件> --output <成片> --ffprobe <可执行文件>`；图片输入时改用 `--kind photo`。脚本拦截意外降尺寸或视频降帧，已确定的特殊画幅可明确使用允许缩放参数。它只核对技术规格，仍需抽看实际导出帧。对含文字的画面，要把原图、预览帧和成片帧按实际观看尺寸对照；若导出把原本可读的字压糊，就调整缩放、运动或编码后重新验收。

最终使用绝对路径展示本地视频。将用户反馈和本次新发现保存在输出项目记录里，便于下一次迭代。不要把视觉效果认可表述为自动分层、任意截图一键生成或付费需求已被验证。
